# Technical-Debt Audit — `src/chaos_librarian`

> Audit date: 2026-05-29. Scope: `src/chaos_librarian/` (~30k LOC, Python 3.13). Excludes
> tests, docs, schemas, generated `chaos-test-out/`, `.venv`, and lockfiles. Surfacing only —
> no code was changed. Generated by a 10-unit scan → per-unit adversarial verification →
> synthesis workflow (21 agents; 32 confirmed, 4 dropped).

## (A) Summary

This audit consolidates **32 verified findings** across 10 source units. No Critical or High findings survived verification; the debt is uniformly **Medium/Low** maintainability and consistency debt in a healthy ~30k-LOC codebase. **Category 1 (TODO/FIXME/HACK markers) was empty repo-wide** — no stale markers were found.

The dominant themes are **systemic cross-unit duplication** and **undocumented magic literals**:

1. **The same 13-field "context/topology key" construction is copy-pasted across at least three units.** The `topology_key()` builder appears 4× in `adapter/` (index.py + compare.py), and the structurally identical 13-field `AssetContext` construction appears 3× in `topology.py` (`_movie/_episode/_track_asset_contexts`). Any change to the shared shape must be synchronized across 7+ sites in two units — neither scanner could see the other's half. This is the highest-leverage refactor in the report (D-001).

2. **A `start/commit` pairing-validation algorithm was implemented twice and never converged.** `validation/rules/slow_copy.py` and `network_lag.py` independently re-derive "split timeline by action → validate 1:1 cardinality → report orphans," down to verbatim message templates (D-002, D-008). Separately, the **`_network_lag_*` field accessors are duplicated verbatim** between `materializer/wall_clock.py` and `replay.py`, differing only in the exception class raised (D-003) — the same "two implementations parameterized only by exception type" pattern recurs in the `assert isinstance(entry, CommittedJournalEntry)` narrowing (D-009, D-013), where `replay.py` raises a domain error but `wall_clock.py`/`filesystem.py` rely on bare asserts.

3. **Duplicate-detection ("seen dict") logic is reimplemented across many validation rules** — `id_duplicate`, `path_duplicate`, `sidecar_language`, and `hierarchy` each hand-roll a visited-key map with first-location reporting (D-007). This is a genuine systemic validation pattern, though value-type and severity differences make a single abstraction debatable.

4. **The SHA256 URI regex is hardcoded 11× across the contract layer** despite `content_sources.py` already exporting `SHA256_URI_PATTERN` (D-004) — a constant exists but isn't reused. More broadly, **Category 9 (magic literals) is the single largest category**: unexplained numeric defaults and bounds in `contract/scenario.py`, the `generation_planner.py` fixture generator, the repeated `2048`-byte stderr-tail buffer across 5 tooling modules (D-006), and the cover-art `'320x320'` literal.

**Genuine (non-cosmetic) behavioral risks**, all Medium, are isolated and few: a silent `(640, 480)` fallback on unknown resolution that masks bad input where sibling helpers raise (D-005); an uncaught `UnicodeEncodeError` on `iso-8859-1` subtitles with non-Latin-1 text (D-010); and dropped HD-segment evidence in resolution-switch synthesis (D-011). Categories **4, 6, 8, and 10 yielded nothing**; Category **2 (dead code)** produced only one finding (dropped output, not unreachable code — D-011).
