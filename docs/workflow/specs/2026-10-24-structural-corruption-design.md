## Author interface

`corrupt_container_header.region` optionally selects `mp4_moov` or `mkv_cues`.
A structural region cannot accompany a non-null `bytes` field. Without a region, omitted
bytes still means 64. `truncate_file.boundary: mp3_after_16_frames` is mutually exclusive
with non-null `keep_bytes`; exactly one truncate selector is required.
Selectors are stable names, not arbitrary byte expressions. Scenario version becomes 36
and replay-bundle version 15 (embedded scenario YAML). No report model gains a field:
existing metadata and nullable byte spans already express intent and actual evidence.

| Selector | Supported input | Mutation | Feature proof |
| --- | --- | --- | --- |
| mp4_moov | generated H.264 MP4 | zero four bytes of the top-level moov type | failed ffprobe |
| mkv_cues | generated H.264 MKV | zero four bytes of Segment-child Cues ID | probeable and linearly decodable |
| mp3_after_16_frames | generated MP3 audio | keep through audio packet 16 | 16 complete frames, shorter decoded PCM |

MP4/MKV permit ordinary synthetic video at 480p or smaller and at most one AAC audio
stream, MP3 exactly one MP3 stream at 44.1 kHz and at most two channels. Duration is finite
in (0,30] seconds. No imported, same-content, hardlink or symlink assets, embedded extras,
advanced video/muxing profiles or explicitly authored track dispositions. MP4 moov placement
at start/end is supported. Structural assets may undergo placement/path-only operations,
but other byte/track-changing operations and repeated structural mutations are rejected.
The validation rejection happens before creating a run directory. Actual missing structures,
short MP3 inputs, malformed lengths or excessive generated size fail before replacing media.

## Resolution and evidence

The engine records selector intent with null unresolved byte spans; it never guesses
encoded offsets. Journal delta and manifest corruption metadata retain region/boundary;
version-history summaries preserve them. Materialization resolves the actual generated bytes.
The existing corruption report stores actual byte_start/count, input/output sizes/hashes,
selector metadata and observed probe outcome. A failed media probe is intentional evidence;
timeout, launch failure and output-limit failure are infrastructure failures, not coverage.
No runtime decode guarantee or downstream recovery policy is inferred from probe success.

MP4 walks top-level box headers, honoring 32-bit, extended and end-of-file lengths, requiring
forward progress and bounds before arithmetic/slicing. It requires an ftyp and exactly one
moov; type damage never touches size fields. MKV validates the EBML header and Segment,
walks only Segment's immediate children, and finds exactly one Cues. IDs are 1–4 bytes,
sizes 1–8; unknown-size Segment may extend to EOF, unknown-size children are rejected.
There is no raw magic search or recursive parser. At most 4096 elements are visited.
Both locators return one (offset,4) span and reject malformed/duplicate/missing structures.
MP3 reuses packet probing for the first 16 audio frames, verifies monotone contiguous,
positive in-file spans and that truncation leaves a nonempty removed suffix. Supported MPEG
frame headers are checked against packet lengths; too few frames produce an actionable error.

Structural reads cap at 64 MiB plus one detection byte before allocation; synthesis uses
ffmpeg duration/file caps and 1 MiB captured-output limits, with existing 60s timeout.
Packet and post-mutation probes have 1 MiB captured-output caps and existing 15s timeout.
Limits are feature-scoped. Offsets are checked against actual bytes, never metadata size alone.
Existing path containment, staging, atomic sibling replacement and run failure reporting apply.
Replay re-resolves selectors against the same generated input and records actual results;
repeatable recipe selection is promised, cross-toolchain byte-identical encoding is not.

## Failure model

Accepted: malformed or truncated box/EBML/frame headers; false marker bytes in payload;
missing Cues/moov; unknown sizes; duplicate structures; huge advertised lengths; exhausted
visit/file/output/runtime limits; unsupported assets/actions; short MP3; tool failure; and
failure before atomic replacement. Tests must distinguish invalid-media exit from infrastructure
failure. Existing containment behavior remains protected by repository tests.
Out of deployment: imported arbitrary media and concurrent hostile writers altering staged
files; structural selectors explicitly reject imported/alias assets, and run staging is owned
by one materializer. No new concurrency or filesystem security contract is introduced.

## Success and validation

Contract tests cover omitted legacy selectors, accepted selectors and mutual exclusion,
invalid names, serialization round trips and generated schemas. Validation tests reject the
unsupported matrix and mutation combinations before output creation. Engine tests distinguish
requested/unresolved metadata from resolved reports and retain version-history selectors.
Parser tests cover tiny/truncated/oversize/zero/extended headers, payload decoys, unknown-size
Segment versus child, duplicate targets, 4096-node budget, and real frame boundary checks.
Handler tests assert exact changed span/prefix, hashes, bounded read, non-publication on
resolution failure and tool-limit classification. New tests are observed red before code.
Real CLI materialize tests generate healthy controls, independently inspect structures and
compare exact changed bytes, invoke bounded ffprobe and decode for claimed readable cells,
count retained frames/PCM, and exercise same-toolchain replay. MP3 advertised duration is
not proof: Xing metadata can retain the original duration after truncation.
Run focused tests then repository lint/types/schema and both final suite arms with zero skips.
